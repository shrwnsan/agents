# Global agent rules

Every harness, every repo. Repo AGENTS.md/CLAUDE.md wins on conflict.
Chat: telegraph ok, noun phrases ok, no filler. Commits, PRs, docs: plain full sentences.
Unsure? Read more code, then ask with short options.

## Workspace
- Owner: GitHub `shrwnsan`. Repos: `~/Developer/{personal,forked,sandbox}`. Site repo: `shrwnsan.github.io`.
- Missing repo: clone `https://github.com/shrwnsan/<repo>.git` into the matching folder.
- Stay in the current repo, or the project the user names.
- Dotfiles: a local `dotfiles/` or `.dotfiles/` repo manages config in `~`. Before changing config there, read that repo's AGENTS.md.
- Unexpected changes: another agent or the user made them. Don't revert; stay on task.

## Files
- Delete with `trash`, never `rm -rf`.
- Paths in code, docs, and commands: `~` or `$HOME`, never `/Users/<name>`.
- Edit before creating. Split files past ~500 LOC.

## Security
- Never open or print secrets files: `.env*`, `*.key`, `*.pem`, `credentials.json`, `~/.aws/credentials`, `.npmrc` with tokens.
- Never print env var values (`env`, `printenv`, `echo $SOME_KEY`). Check presence only: `[ -n "$VAR" ]`.
- Secret found in code: report where, never the value. Reviews: flag hardcoded secrets and secrets files missing from `.gitignore`.
- Before committing: no secrets files in `git diff --cached --name-only`.

## Git
- Conventional Commits: `type(scope): summary` (feat, fix, refactor, docs, chore, test, ci). Small, reviewable commits.
- Trailer for the model that wrote the change:
  - Claude: `Co-Authored-By: Claude <noreply@anthropic.com>`
  - GLM: `Co-Authored-By: GLM <zai-org@users.noreply.github.com>`
  - OpenCode (any model): `Co-Authored-By: OpenCode <noreply@opencode.ai>`
  - Other: that model's usual format.
- Harness-added trailers are fine. No "Generated with ..." lines in commit messages.
- Main checkout (the primary working tree): never create or switch branches there. Commit there only when asked.
- New branch: ask first unless the task implies one (e.g. "open a PR"). Always as a worktree: `git worktree add .worktrees/<branch> -b <branch>`. Work and commit there; push from there when asked.
- `.worktrees/` must be ignored: `git check-ignore -q .worktrees`. If that fails, add it to `.git/info/exclude`, not a tracked `.gitignore`.
- Push or amend only when asked.
- Only on explicit request: `reset --hard`, `clean`, `rebase`, force push, `branch -D` (one exception below), discarding uncommitted work.
- After merge, clean up:
  - `git -C .worktrees/<branch> status --short --ignored`: trash anything beyond build output and dependencies (e.g. `.env`, local data). `git worktree remove` deletes ignored files permanently.
  - `git worktree remove .worktrees/<branch>`. It refuses on uncommitted work or submodules; ask before `--force`.
  - `git branch -d <branch>`. After a squash merge it refuses even though the work landed: if `gh pr view <branch> --json state,headRefOid` shows `MERGED` and `headRefOid` equals `git rev-parse <branch>`, use `-D`; otherwise ask.
- HTTPS remotes.

## GitHub
- Use `gh`, not web URLs: `gh pr view/diff`, `gh pr view <n> --comments`, `gh issue view <n> --comments`, `gh run list/view`.
- Review replies: cite the fix and file:line; resolve threads once it lands.
- Issues, PRs, and comments you write end with `🤖 Generated by <Tool> - <model>`. Model from your system prompt or config; omit it rather than guess.

## Quality
- Before handoff: lint, typecheck, tests. CI red: `gh run view <id> --log-failed`, fix until green.
- Fix root causes, not symptoms. Match repo patterns. Simple, direct code; no speculative abstractions.
- Conflicting instructions: say so, take the safer path.
- Bug report: failing test first, then fix, then confirm it passes.
- Complex or browser repro: plan in `./.agents/debug/test-plan-YYYYMMDD-HHMM-<brief>.md` first; delete after the fix unless worth keeping.

## Subagents (if your harness has them)
- Fan out parallel work (doc sweeps, reviews, mechanical edits, research). Keep judgment and synthesis in the main thread.
- Write tasks a small model can run: exact paths, exact edits, how to verify, "do not commit".

## Docs
- Name: `<prefix>-NNN-<slug>.md`; NNN = highest existing number for that prefix + 1.
- Prefixes: research, eval, prd, adr, tasks, guide, retro. Folder layout: `docs/guides/guide-006-doc-organization.md` in the dotfiles repo.
- Read relevant docs before coding; update them when behavior or APIs change.

## Stacks
- Node: repo's package manager and lockfile; `npm ci` in CI.
- `~/.npmrc` sets `ignore-scripts=true`; keep it. Trusted package that needs install scripts (esbuild, sharp, native addons): `npm rebuild <pkg> --ignore-scripts=false`.
- New direct deps: exact versions (`npm i -E`) unless the repo uses ranges. Never rewrite existing specifiers.
- Python: the repo's venv/poetry/pipenv/uv setup; respect pyproject.toml and requirements.txt.
- Shell: POSIX sh for portable scripts; otherwise match the repo.
- Browser automation: `agent-browser`: `open <url>`, `snapshot -i`, `click @e1` / `fill @e2 "text"`, re-snapshot. Missing: ask before installing.
